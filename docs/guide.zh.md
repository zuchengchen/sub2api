## 先照着做一遍

第一次使用本站，不需要先弄懂所有技术词。按下面 6 步操作即可：

1. 打开[注册页面](/register)，创建账户并登录。
2. 进入[购买兑换码](/redeem-store)，买一张需要金额的兑换码。
3. 打开[兑换余额](/redeem)，粘贴兑换码，把金额加到本站账户。
4. 进入[API Key 管理](/keys)，创建一个 API Key。
5. 在 API Key 页面点击“使用密钥”，复制 Codex 配置。
6. 使用 Codex 后，到[用量记录](/usage)确认是否成功，并查看花费。

这里先记住两个词：

- **兑换码**：一串买来的字符。把它填到“兑换余额”页面后，金额才会进入本站账户。
- **API Key**：可以把它理解为“软件专用密码”。Codex 用它识别你的账户，必须像登录密码一样保管。

> 本站有三个可用网址，但它们连接的是同一个账户系统。无论从哪个网址登录，账户、余额、API Key 和使用记录都是同一份，不需要重复注册或充值。

## 注册与登录

### 创建账户

1. 打开[注册页面](/register)。
2. 按页面提示填写信息。
3. 如果页面要求验证邮箱，就先去邮箱完成验证。
4. 登录后，看一眼页面右上角，确认显示的是自己的账户。

如果注册页面提示“暂不开放”或“需要邀请码”，说明当前不能直接注册。请以页面提示为准，不要连续重复提交。

### 保护账户

- 密码不要和其他网站共用。
- 不要把密码、验证码或完整 API Key 发到群聊或公开帖子。
- 使用公共电脑后要退出登录。
- 发现不是自己产生的使用记录时，先删除或停用相关 API Key，再联系管理员。

## 充值：先买兑换码，再兑换余额

本站充值分成两步：**先购买兑换码，再回本站兑换余额**。买完兑换码不等于已经充值，必须完成第二步。

### 第一步：购买兑换码

1. 登录本站，打开[购买兑换码](/redeem-store)。
2. 选择需要的金额。
3. 按购买页面的提示完成付款。
4. 付款后保存订单号和兑换码。

购买页面可能由其他商店提供，页面样式、价格和交付方式可能会变化。请以购买时看到的页面为准。

兑换码相当于未使用的充值凭证。不要截图发给别人，也不要在群聊里展示完整内容。

### 第二步：把兑换码换成余额

1. 回到本站，打开[兑换余额](/redeem)。
2. 完整粘贴兑换码。
3. 检查开头和结尾没有空格，然后提交。
4. 看到“兑换成功”后，回到控制台查看余额。

一张兑换码通常只能成功使用一次。已经显示成功后，不要再次提交。

### 兑换不成功怎么办

- **提示“格式错误”**：重新复制兑换码，并删除前后的空格或换行。
- **提示“无效”或“已使用”**：核对订单和兑换记录，不要连续反复尝试。
- **显示成功，但余额没有变化**：刷新页面；仍没有变化时，退出后重新登录。
- **还是不能解决**：私下联系管理员，提供订单号、购买时间和页面提示。截图前遮住密码、API Key 和完整兑换码。

## API Key：给软件使用的专用密码

Codex 不能直接使用你的登录密码，它需要 API Key 来连接本站。

### 创建 API Key

1. 打开[API Key 管理](/keys)。
2. 点击“创建 API Key”。
3. 填一个自己看得懂的名称，例如“我的电脑”或“Codex”。
4. 如果页面要求选择分组，可以先选择日常使用的分组；不确定时以页面说明为准。
5. 测试用的 Key 建议设置额度，避免意外产生太多费用。
6. 创建后妥善保存。页面如果只显示一次，请当场复制。

“分组”是页面提供的不同服务选项，可能影响可用模型和费用。不确定选哪个时，先看创建页面上的说明。

### 怎么保管

- 每台电脑或每个软件单独创建一个 API Key。以后出问题时，只需停用对应的那一个。
- 不要把 API Key 写进公开代码、帖子、截图或聊天记录。
- 不要把自己的 API Key 借给别人，也不要出售账户或 Key。
- 不再使用的 API Key 要删除或停用。
- 经常查看[用量记录](/usage)。看到陌生时间、模型或费用时，立即停用相关 Key。

## 检查 API Key 能不能用

如果你只打算使用 Codex，可以直接跳到下一节。这里的命令用于检查 API Key 和网址是否填写正确。

下面用 `key66.cc.cd` 举例。命令中的 `<你的 API Key>` 要换成你刚创建的 Key，尖括号也要一起删掉。

### macOS、Linux 或 WSL

```bash
export SUB2API_API_KEY="<你的 API Key>"
curl https://key66.cc.cd/v1/models \
  -H "Authorization: Bearer $SUB2API_API_KEY"
```

### Windows PowerShell

```powershell
$env:SUB2API_API_KEY = "<你的 API Key>"
curl.exe https://key66.cc.cd/v1/models `
  -H "Authorization: Bearer $env:SUB2API_API_KEY"
```

成功时，窗口会显示一段模型列表。失败时通常会看到一个三位数：

- `200`：连接成功。
- `401`：API Key 没填、填错、已经停用或已经过期。
- `403`：当前账户或分组不能使用这个模型。
- `404`：网址可能填错，重点检查结尾有没有 `/v1`。
- `429`：短时间使用次数太多，或者额度受到限制。稍等后再试，并检查余额和 Key 额度。

这些数字叫“状态码”，只是帮助判断问题的位置，不需要背下来。完整的对照表和处理方案见[错误码含义与处理方案](#error-codes)。

## 在 Codex 中使用本站

### 推荐方法：直接复制配置

1. 打开[API Key 管理](/keys)。
2. 找到刚创建的 API Key。
3. 点击“使用密钥”。
4. 找到 Codex 配置并复制。
5. 按页面提示放到 Codex 配置文件中。
6. 关闭并重新打开 Codex。

这种方法最省事，也最不容易填错。下面的手工方法只在无法直接复制时使用。

### 手工填写配置

Codex 的配置文件名是 `.codex/config.toml`：

- Windows 通常在 `C:\Users\你的 Windows 用户名\.codex\config.toml`。
- macOS 和 Linux 通常在自己的用户文件夹下，即 `~/.codex/config.toml`。

找到文件后，把下面内容放进去：

```toml
model_provider = "sub2api"
model = "gpt-5.5"

[model_providers.sub2api]
name = "Sub2API"
base_url = "https://key66.cc.cd/v1"
env_key = "SUB2API_API_KEY"
wire_api = "responses"
requires_openai_auth = false
supports_websockets = false
```

不用逐个理解所有英文，重点检查：

- `base_url` 是本站服务地址，结尾必须有 `/v1`。
- `env_key` 是存放 API Key 的名称，不是 API Key 本身。
- `model` 是要使用的模型名称。
- `model_provider` 是这组配置的名称。测速工具不会修改或切换它。

保存配置后，在准备启动 Codex 的 PowerShell 窗口输入：

```powershell
$env:SUB2API_API_KEY = "<你的 API Key>"
codex
```

第一行把 API Key 临时交给 Codex，第二行启动 Codex。关闭这个 PowerShell 窗口后，临时填写的 Key 会消失，不会被写进教程或代码。

## 自动选择速度最快的网址

这个工具只适用于 **Windows**。它会测试几个本站网址，然后把 Codex 改成速度最快的那个。

下载地址：[下载自动测速工具](/downloads/select-fastest-codex-base-url.bat)

SHA-256（可以理解为文件的“指纹”）：`4bef37d6600d0d77101794cb9f0059554e60f751dc7e5b2cde3e9dc67eb9a43b`

### 运行前先确认

1. 你已经成功配置过 Codex，配置中已经有 `base_url`。
2. 关闭所有 Codex 窗口。
3. 下载 BAT 文件和同名的 `.sha256` 文件，并放在同一个文件夹。
4. 右键 BAT 文件，选择“以管理员身份运行”。

BAT 文件就是下载下来的测速工具。工具需要管理员权限，因为它会修改 Windows 的 `hosts` 文件。可以把 hosts 理解成电脑自己的“网址通讯录”。

### 建议先核对文件指纹

在 BAT 文件所在文件夹打开 PowerShell，输入：

```powershell
(Get-FileHash .\select-fastest-codex-base-url.bat -Algorithm SHA256).Hash.ToLower()
Get-Content .\select-fastest-codex-base-url.bat.sha256
```

屏幕会显示两行很长的字符。两行开头必须完全一样。不一样时不要运行，请重新下载。

### 工具会做什么

1. 先备份 Codex 配置和 Windows hosts 文件。
2. 测试下面四个网址：
   - `https://mofa.love.gd`
   - `https://key66.vip`
   - `https://mofayaoshipu.cc.cd`
   - `https://key66.cc.cd`
3. 每个网址测试三次，减少一次偶然变快或变慢造成的影响。
4. 选择能正常连接且速度最快的网址。
5. 只会更换当前 Codex 配置中的网址域名，原来的 `/v1` 和其他设置保持不变。
6. 修改后再检查一次；如果中途失败，会尝试恢复刚才的备份。

`key66.vip` 只是测速时的候选网址，不属于前面承诺的三个稳定网址。它打不开时，工具会继续测试其他网址。

工具还会把 `mofa.love.gd` 记录到 Windows 的网址通讯录中，对应地址为 `15.204.82.11`。成功后这条记录会保留。

### 工具不会做什么

- 不会创建或切换 Codex 的配置分组。
- 不会读取、询问或修改 API Key。
- 不会修改模型名称和其他设置。
- 不会删除以前留下的备份。

也就是说，你不需要在这个工具里输入 API Key。

### 怎么看运行结果

运行结束后，窗口会列出每个网址的速度，并告诉你最终选择了哪个网址。它还会显示两个备份文件放在哪里。

如果四个网址全部失败，Codex 的服务地址不会改变。请先检查电脑能否正常上网，稍后再试。

### 想恢复原来的设置

1. 在工具最后的输出中，找到两个以 `.bak` 结尾的备份文件。
2. 关闭 Codex。
3. 用管理员 PowerShell 把两个备份分别复制回原来的位置。
4. 输入 `ipconfig /flushdns` 并按回车。
5. 重新打开 Codex。

如果不知道怎样恢复，不要删除备份文件，直接把工具最后显示的文件名发给管理员。不要发送备份文件的内容，因为里面可能有你的个人配置。

## SVIP 能得到什么、需要注意什么

### 怎样成为 SVIP

- 账户总余额必须**严格大于 100 元**，系统才会自动升级。
- 余额正好是 100 元时不会升级。例如 100 元不可以，100.01 元可以。
- 升级成功后会一直保留 SVIP，目前不会因为余额降低而自动取消。
- 成为 SVIP 后，系统会冻结 100 元作为保留金额。这 100 元仍显示在总余额中，但不能用于平时调用。

举例：总余额是 150 元时，可用余额约为 50 元；总余额是 100.01 元时，可用余额约为 0.01 元。

### SVIP 可以得到什么

| 权利 | 通俗说明 |
| --- | --- |
| 专属模型 | 可以使用 `gpt-5.6-luna` 及它的同系列版本 |
| 分组优惠 | 使用 `gpt-pro` 分组时，计费倍率减 0.05，最低不会小于 0 |
| 有效时间 | 达到条件并升级后长期有效 |
| 站内服务 | 可以使用页面中标明的 SVIP 功能 |

“倍率”是系统计算费用时使用的数字。不同模型和分组的费用仍可能不同，请以实际使用记录为准。

SVIP 不代表所有模型永远都能使用，也不保证每次请求都成功。模型提供方维护、账户可用余额和本站维护都可能造成暂时不可用。

### SVIP 用户需要遵守什么

- 保护好账户、密码和 API Key，不共享、不出租、不转卖。
- 不使用本站进行攻击、欺诈、滥用或违法活动。
- 遵守站点规则和当地法律。
- 自己承担本账户产生的请求和费用。
- 注意可用余额。被冻结的 100 元不能用于日常使用。

违反规则时，站点可能限制模型、API Key、账户或其他服务。

## 错误码含义与处理方案

出错时，屏幕上一般会出现三种线索。看懂任意一种就够了：

- **一个三位数**，例如 `401`、`429`。它叫“状态码”，用来说明问题大概出在哪一层。
- **一串大写英文加下划线**，例如 `INSUFFICIENT_BALANCE`。本教程叫它“具体原因代号”，它比三位数更精确。
- **一个小写英文单词组合**，例如 `rate_limit_exceeded`。它是错误的“分类名”，出现在 `type` 位置。

完整的错误内容通常长这样，三种线索经常同时出现：

```json
{
  "error": {
    "type": "rate_limit_exceeded",
    "message": "user requests-per-minute limit exceeded"
  }
}
```

不需要背这些代号。看到问题时回到本节查表即可。

### 先看三位数

| 三位数 | 大概意思 | 先做什么 |
| --- | --- | --- |
| `200` | 成功 | 不用处理 |
| `400` | 请求内容本身有问题，通常是模型名或参数填错 | 检查模型名称是否和[模型广场](/model-plaza)一致 |
| `401` | 没有通过身份验证，几乎都是 API Key 的问题 | 重新复制 API Key，删掉前后空格，然后重启 Codex |
| `403` | 身份没问题，但这次不允许，可能是余额不足或没有该模型权限 | 先看[控制台](/usage)的“可用余额”，再确认分组是否包含这个模型 |
| `404` | 地址或资源不存在 | 重点检查服务地址结尾有没有 `/v1` |
| `409` | 和已有数据冲突，例如名称重复 | 按页面提示换一个名称再提交 |
| `413` | 发送的内容太大 | 缩短对话或减少一次发送的文件，然后重试 |
| `429` | 太频繁，或某个限额已经用完 | 等一会儿再试；反复出现时查限额和余额，见下面两张表 |
| `499` | 请求被自己这边中断了，例如提前按了 Ctrl+C 或关掉窗口 | 属于正常现象，重新发送即可 |
| `500` | 本站内部出错 | 稍后重试；持续出现时联系管理员 |
| `502` | 本站正常，但上游模型服务这次没成功 | 稍后重试，或换一个模型再试 |
| `503` | 暂时没有可用的服务资源 | 等几分钟再试，不要连续快速重试 |
| `504` | 上游响应太慢，超时了 | 缩短请求内容后重试，或换一个模型 |

`400` 到 `499` 通常是这次请求或账户状态的问题，改一下就能解决；`500` 及以上一般不是你的操作造成的，等待或重试更有效。

### 再看具体原因代号

这些代号出现在错误文字里，比三位数更能说明该做什么。

| 代号 | 含义 | 处理方案 |
| --- | --- | --- |
| `INSUFFICIENT_BALANCE` | 可用余额不够（返回 `403`） | 打开[购买兑换码](/redeem-store)买一张，再到[兑换余额](/redeem)兑换 |
| `API_KEY_EXPIRED` | 这个 API Key 已过期（返回 `403`） | 到[API Key 管理](/keys)新建一个，并更新 Codex 配置 |
| `API_KEY_QUOTA_EXHAUSTED` | 这个 Key 自己设的额度用完了（返回 `429`） | 在 API Key 管理里调高额度，或换一个 Key |
| `API_KEY_RATE_5H_EXCEEDED` | 这个 Key 的 5 小时限额用完了（返回 `429`） | 等限额窗口过去，或换一个 Key |
| `API_KEY_RATE_1D_EXCEEDED` | 这个 Key 的一天限额用完了（返回 `429`） | 等第二天，或换一个 Key |
| `API_KEY_RATE_7D_EXCEEDED` | 这个 Key 的 7 天限额用完了（返回 `429`） | 等限额窗口过去，或换一个 Key |
| `USER_RPM_EXCEEDED` | 你这一分钟发的请求太多了（返回 `429`） | 等下一分钟；把并行任务数量调小 |
| `GROUP_RPM_EXCEEDED` | 当前分组这一分钟太忙了（返回 `429`） | 稍等重试，或换一个分组 |
| `USER_PLATFORM_DAILY_QUOTA_EXHAUSTED` | 今天在这个平台的用量额度用完了（返回 `429`） | 等额度重置；错误信息里通常会带重置时间 |
| `USER_PLATFORM_WEEKLY_QUOTA_EXHAUSTED` | 本周额度用完了（返回 `429`） | 同上，等窗口重置 |
| `USER_PLATFORM_MONTHLY_QUOTA_EXHAUSTED` | 本月额度用完了（返回 `429`） | 同上，等窗口重置 |
| `SUBSCRIPTION_INVALID` | 订阅无效或已过期（返回 `403`） | 确认订阅状态，或改用余额计费的分组 |
| `BILLING_SERVICE_ERROR` | 计费服务暂时不可用（返回 `503`） | 这不是你的问题，稍后重试即可 |

看到 `429` 时先分清是哪一种：**限额用完**要等窗口重置，**发得太快**只要放慢速度就能马上恢复。

### 最后看分类名

有些客户端只显示 `type` 这个分类名。对照如下：

| 分类名 | 说明 | 处理方向 |
| --- | --- | --- |
| `authentication_error` | 身份验证失败 | 检查 API Key |
| `permission_error` | 没有这次操作的权限 | 检查分组和模型权限 |
| `billing_error` | 余额或计费相关 | 检查可用余额 |
| `invalid_request_error` | 请求内容有问题 | 检查模型名、参数和请求大小 |
| `not_found_error` | 找不到对应资源 | 检查服务地址和模型名 |
| `rate_limit_exceeded` | 触发了限流或限额 | 等待后重试，见上面的代号表 |
| `rate_limit_error` | 同样表示被限流，多为并发或排队已满 | 减少同时进行的请求数量 |
| `upstream_error` / `provider_error` | 上游模型服务出错 | 稍后重试或换模型 |
| `api_error` / `server_error` | 服务端错误 | 稍后重试；持续出现时联系管理员 |
| `overloaded_error` | 服务当前过载 | 等几分钟再试 |

`rate_limit_exceeded` 和 `rate_limit_error` 两种写法都表示“被限流了”，处理方式一样：先放慢，再看是不是限额用完。

### 关于自动重试

被限流时，返回内容里可能带一个叫 `Retry-After` 的数字，单位是秒，表示建议等待多久。大部分客户端会自动按它退避重试，通常不需要手工处理。

如果自己写脚本调用，建议看到 `429` 时按这个数字等待，而不是立刻重试。连续快速重试只会让限额恢复得更慢。

## 遇到问题先看这里

### 显示 401

API Key 没通过验证。重新复制 Key，检查前后没有空格，并确认它没有被停用，然后关闭并重新打开 Codex。其他三位数的含义见[错误码含义与处理方案](#error-codes)。

### 提示余额不足

查看“可用余额”，不要只看“总余额”。SVIP 用户有 100 元被冻结，不能用于平时调用。余额不够时，需要重新购买兑换码并兑换。对应的代号是 `INSUFFICIENT_BALANCE`。

### Codex 提示找不到 provider

`provider` 可以理解为“Codex 配置分组”。最简单的处理方法是回到[API Key 管理](/keys)，点击“使用密钥”，重新复制一份 Codex 配置，然后重启 Codex。

### 某个网址打不开

先换成“三个可用网址”中另外一个。账户和余额不会改变。如果运行过测速工具，可以再次运行，让工具重新选择。

### goal-workflow 安装后不能用

先完全退出并重启 Codex。仍不能用时，检查安装地址是否包含完整的 `tree/master/skills/goal-workflow`，不要重复安装到多个文件夹。

### 测速工具显示全部失败

先用浏览器打开三个稳定网址。如果都打不开，通常是当前网络有问题，可以稍后再试。工具全部测试失败时不会更改 Codex 的服务地址。

### 测速工具提示“配置不支持”

不要随意删除配置内容。回到[API Key 管理](/keys)，使用“使用密钥”重新生成 Codex 配置，再运行测速工具。

## 保护账户和密钥

- 示例中的 `<你的 API Key>` 只是提示文字，必须换成自己的 Key，但不要把真实值发给别人。
- 下载 BAT 后，建议先核对 SHA-256 文件指纹。
- 不要运行群聊或陌生网站提供的修改版测速工具。
- 不要为了消除报错而关闭浏览器或 PowerShell 的安全检查。
- 备份文件只保存在自己的电脑上，不要上传。
- 联系管理员时，永远不要发送密码、完整 API Key、验证码或 Cookie（浏览器登录信息）。

## 联系管理员时要准备什么

为了更快解决问题，可以准备：

- 问题发生的大概时间。
- 当时使用的是哪个网址。
- 页面或 Codex 显示的错误文字。
- 使用的模型、分组和 Codex 版本。
- 兑换问题对应的订单号和购买时间。
- 测速问题对应的结果和备份文件名。

截图或复制错误前，先遮住密码、完整 API Key、完整兑换码和个人信息。管理员不需要这些秘密信息来判断普通问题。
