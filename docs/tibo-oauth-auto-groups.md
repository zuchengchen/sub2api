# Tibo 自动分组

OpenAI 平台的「GPT-福利」与「GPT-不降智」组成自动分类范围。已有 Tibo 探测每次得到新的明确结果时，红点把 GPT OAuth 账号移入福利组，绿点移入不降智组。采用单次红绿点，不等待后台的多次投票确认；连续不同结果可能使账号来回切换。

账号必须已经属于至少一个目标分组。混合分组账号保留其他组的关联、优先级及创建时间；完全位于其他分组、未分组、API Key、Setup Token 和其他平台的账号不参与。一个账号同时属于两个目标组时，按结果保留一个。暂停状态不会因切组而恢复。

复用现有 `gateway.openai_tibo_route` 配置：默认间隔 10 分钟，随机浮动 ±5 分钟；额度、限流、过期、禁用及探测并发限制继续生效。请求失败或结果未知不切组，重启也不会根据旧记录批量搬组。目标分组缺失、改名或不可用时跳过；不会自动创建分组。

「GPT-不降智」禁止客户端直接选择或调用 Luna，包括已识别的版本及别名。HTTP 与 Responses WebSocket 的每个生成请求均检查，标准模型列表、详情和 Codex 目录同步排除 Luna。该组采用“其他模型放行”的有效规则，原白名单保存值不被改写；余额、全局退役及实际上游能力仍决定请求能否成功。已有具体模型别名和 Codex 自动模式的显式配置继续用于目录枚举。

同一账号经其他组请求时遵循其他组原有规则；该限制不写入账号全局模型设置。生图的公开模型如 `gpt-image-2` 仍然可用，内部 Luna 驱动保留。

新用户注册自动创建两个独立 API Key，名称和绑定分组分别为 `GPT-不降智`、`GPT-福利`，替代原先绑定 `GPT-PRO` 的单个 `GPT` Key。邮箱和第三方注册共用此规则；已有用户的 Key 不回填、不改绑。两个目标组必须存在、启用且属于 OpenAI 平台；缺组或数据库失败会记录初始化错误，注册本身保持成功。两把 Key 与必要的独占普通组访问授权在同一事务提交，避免留下半完成的初始化；不会额外赠送余额或订阅。

自动分组、探测记录及旧/新分组的调度通知在同一事务提交。后台只更新或删除已有的目标关联，不会用旧快照重建全部分组。日志中的 `[TiboAutoGroup]` 记录账号 ID、结果、原组和目标组；失败同时由探测持久化日志记录，不输出凭据。并发冲突会有限重试，持续失败等待下次新探测。立即缓存刷新失败时，已提交的通知继续支持后续传播。

关闭 `gateway.openai_tibo_route.enabled` 会停止探测及自动切组，同时隐藏既有红绿点。这不会取消不降智组的 Luna 禁令。需要整体撤回功能时，回滚本次代码；生产回滚必须遵循仓库发布流程。历史分组不会自动逆向还原，可依据切组日志和备份恢复。若管理员不希望某个账号继续参与，应将它移出两个目标组。

本功能开发交付不包含生产数据库调整或部署。部署前确认两个组的准确名称、OpenAI 平台及启用状态，并按 AGENTS.md 完成版本、标签、GitHub Release、前端重建与 embed 构建等步骤。
