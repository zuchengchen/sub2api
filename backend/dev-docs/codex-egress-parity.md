# Codex OAuth 出站行为与验证

本项目以固定的官方 Codex 版本为协议依据，分别验证请求语义、实际传输和调用生命周期。`gn2api` 的改进是实现参考；不能仅凭两个网关的行为相同，就认定它们符合官方客户端。

本轮固定基准是 `rust-v0.166.0`，源码提交
`6ff1e1ca3b30fc8b914720681fcf5fe62e95f856`。参考客户端必须来自同一发布的完整安装包，包含 CLI、code-mode host、exec server 和 sandbox helper。源码、二进制摘要、模型目录、平台及有效配置均需进入采样收据。

## 传输与会话边界

客户端 HTTP、客户端 WS、上游 HTTP、上游 WS 是不同维度。原生客户端明确提供的 `previous_response_id` 由客户端管理；网关仅在有充分历史证据时自动为 HTTP→WS 请求推断续传。

自动续传的权威状态属于已经取得独占租约的上游 socket。会话索引用于连接亲和，不能单独证明响应锚点仍在该连接上可用。检查点包含账号、执行作用域、上下文窗口、非传输请求属性、输入与输出摘要和待配对工具调用，不保存问答正文。检查点最多保留 10 分钟、2048 项；其他业务或预热写入会先使旧检查点失效。

完整输入必须与上一轮成功输入和输出的前缀一致。工具调用与真实结果必须双向配对；未知类型、未解析引用、冲突或缺洞的输出、未闭合工具链、失败或未完成终态不会形成自动续传检查点。只规范化固定协议中明确允许的可空字段和追踪字段，保留语义 ID、工具参数、执行元数据和推理密文。`compaction_trigger` 是自动推断的窗口边界，原生客户端显式压缩续接仍保留其契约。

官方允许预热后的空增量，发送形态必须是空数组而非 `null`。HTTP 兼容路径可以合并成功终态输出和已经完成的流中输出来建立完整检查点；这属于网关兼容处理，不应描述为官方客户端逐字相同的缓存实现。

HTTP→WS 的大包检查在自动增量后、任何业务或预热写入前执行，测量最终未压缩 JSON。现有 `gateway.openai_ws.http_bridge_threshold_bytes` 默认 15 MiB。超限且有完整历史时使用完整 HTTP 回放，不能把缩短后的 delta 直接发到无上下文的 HTTP 请求。该本地退出不破坏未写入的健康连接，也不永久禁用整个会话的 WS。

## 请求保真与失败处理

WS 后续帧自己的 turn 元数据优先于握手回退值。预热握手不能把随后业务或压缩帧重新标成 `prewarm`。HTTP 中的 Responses Lite 声明使用 HTTP 头；WS→HTTP 桥接时，应把 WS 专用 metadata 标记投影到相应头部，并从 HTTP body 移除，保留显式头部和业务输入。

已向客户端交付字节和上游已产生语义输出，是两个独立的重放边界。即使非流式客户端尚未收到响应，上游已经生成文本、执行工具、返回图片或计量用量后，也不能因通用读错或账号切换重新提交该回合。失败结果应保留原响应、模型、用量和图片归因；已有 cyber-policy 独立结算路径不得重复计费。

原始传输层必须保持完整短读数据、HPACK 与 stream 顺序、流控额度和取消语义。等待写锁时取消不能消耗未发送的 DATA 窗口；可能已经提交的 POST 不在底层自动重放。压缩字典在同一写锁内更新，解压后的消息同样受读取上限约束。关闭和取消不得无限等待停读的对端，也不得污染下一次操作的 deadline。

Responses、OAuth 登录/刷新、quota 和 Live 各自有独立生命周期，不能用一个通用连接复用或头部模板替代全部端点。默认系统根和自定义 CA 的实际 TLS/ALPN/HTTP 行为必须分别验证。账号、凭据快照、代理和信任配置的隔离不得因复用连接而合并。

## 可观察性

请求级诊断区分：

- `openai_ws_auto_incremental_attempted`：本请求曾实际采用自动增量，后续重连或 HTTP 回退不清除此事实。
- `openai_ws_auto_incremental`：最终 WS 尝试是否采用增量；完整 HTTP 回退为 false。
- `openai_ws_auto_incremental_succeeded`：增量收到成功终态并正常完成交付，完整回放成功不能算作增量成功。
- `openai_ws_auto_incremental_replay`：发生过定向锚点恢复或工具续传的完整回放。
- `openai_ws_auto_incremental_reason`：固定原因枚举；有实际来源时才输出有界的条目类型和索引。

这些诊断不应记录凭据、原始问答、工具参数、密文或私有摘要。排障时不能仅靠 HTTP 200、已连接 WS 或 `attempted=true` 判定一轮成功。

## 验证入口

`backend/tools/codexgolden/README.md` 描述真实 CLI 的本地采样与严格比较。每次使用新输出目录；参考与候选分别产生记录，保留完整 trace、sender ownership、实际 TLS/H2 关联、工具退出状态及有效配置。`passthrough` 与 `ctx_pool` 必须各自实际运行，模式标签不能替代真实连接池获取证据。

比较器只规范化有来源依据的动态值。工具参数、执行结果 metadata、未知扩展字段和大整数必须保持精确；字段名字像时间或 UUID，不代表它属于可忽略的追踪信息。比较器自身须用真实差异、正常动态变化、字段名碰撞、截断记录及缺失场景校准。

`TestCodexOAuthTrafficAcceptance` 需要明确提供官方二进制、参考目录和新的候选目录。未提供输入而跳过时，不构成流量验收。真实 CLI passthrough 场景不能代替 HTTP→WS 自动增量、ctx_pool 元数据、非流式部分输出和 handler 单次结算的回归。

任何真实上游验收都必须有发送前额度控制，包含失败、重试、WS 握手、每个 `response.create` 和附加查询。单纯统计 CONNECT 连接数不能限制任意 WS 消息或共享 HTTP 连接中的请求数。合成采样不得接触生产凭据；失败的真实调用同样占用预算。

本轮具体成功、失败、跳过、性能、真实调用计数及覆盖状态由独立运行报告记录。此文描述实现契约，不表示某个候选版本已经完成全部验收，也不证明 OpenAI 服务端的私有客户端分类结果。

## 开关与回滚

现有全局 `gateway.openai_ws.force_http`、`enabled`、账号 WS mode，以及自动增量、预热和精确传输开关继续保留各自用途。回滚某次代码变更时，需保持已有客户端、计费和持久化契约，并运行对应的模式回归。

生产发布仍遵循仓库 AGENTS.md 的开发分支、集成、版本、`czc-*` 不可变标签和完整 GitHub Release 流程。功能分支的构建和本地验收不构成发布，不能直接替换生产二进制。
